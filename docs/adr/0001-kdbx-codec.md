# ADR 0001 — KDBX codec: clean-room implementation, not KeePassLib

- **Status:** accepted
- **Date:** 2026-08-29
- **Phase:** P0

## Context

AuraVault stores vaults as KDBX 4.1 so the on-disk crypto is a proven, interoperable format rather
than a bespoke one. We need a reader/writer inside `AuraVault.Core`, which by architectural rule
(`ArchitectureTests`) may not reference any UI or OS framework and should keep its dependency
surface minimal and permissively licensed.

Options considered:

1. **`KeePassLib`** (from KeePass 2.x) — the reference implementation. Licensed **GPL-2.0** and
   coupled to `System.Windows.Forms` / `System.Drawing`. Linking it would force AuraVault's license
   and pull UI assemblies into `Core`. Rejected.
2. **Permissive ports** (`KpcLib`, `ModernKeePassLib`) — MIT-ish, but less widely exercised, varying
   KDBX 4.1 completeness, and still a moving third-party surface for the most security-critical code.
3. **Clean-room implementation** in `Core`, built on the documented KDBX format and audited
   primitives.

The KDBX *file format* is not encumbered — only KeePass's *source code* is GPL.

## Decision

Implement `Kdbx4Codec` from scratch in `AuraVault.Core.Kdbx`, behind an `IKdbxCodec` seam so a
port can be dropped in later if needed. Cryptographic primitives come from:

- **Argon2id / Argon2d** — `Konscious.Security.Cryptography.Argon2`
- **ChaCha20 (RFC 8439) / Salsa20** — `BouncyCastle.Cryptography`
- **AES-256-CBC, HMAC-SHA-256/512, SHA-256/512, GZip** — .NET BCL

Scope for P0: KDBX 4.x read + write (AES-CBC and ChaCha20 outer ciphers; Salsa20 and ChaCha20 inner
random streams; GZip or no compression). KDBX 3.1 is detected and rejected with a clear message;
read support for it is a separate, later work item.

## Validation

- Crypto is checked against published KATs (RFC 8439 ChaCha20 keystream) in `AuraVault.Core.Tests`.
- Write→read round-trip is asserted across every cipher/compression combination, covering protected
  fields, custom fields, tags, history and Unicode.
- Wrong-key and single-bit-flip inputs must raise `KdbxIntegrityException` with no partial plaintext.
- **Pending (P1):** `AuraVault.Integration.Tests` will open AuraVault-written files with
  `keepassxc-cli` in CI and diff a dump, plus read fixtures generated by KeePassXC and KeePass 2.x.

## Consequences

- Full control over the format surface; no license or UI-dependency contamination in `Core`.
- We own the correctness risk for security-critical parsing. Mitigated by KATs, round-trip tests,
  cross-implementation fixtures, and a planned fuzz target (`SharpFuzz`) over `Kdbx4Codec.Read`.
- If timelines slip or an edge case proves costly, `IKdbxCodec` lets us swap in `KpcLib` without
  touching callers.
